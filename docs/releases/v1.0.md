## v1.0 — the first release

A native, fully offline 3D visualizer of everything running on this Mac, and of the machines on your own network.
Swift, AppKit and Metal against the macOS SDK: no third-party dependencies, no web view in the UI, no bundled
runtime. Requires macOS 13 or later; Apple silicon and Intel are both built from the same source, but the binary in
this release is built for the runner's architecture.

### The eight views

* **Processes** — the process tree as a 3D cone tree, children above their parent. Size is memory, lane traffic or
  CPU load; glow is CPU. Lanes show what processes exchange: network, disk, and the pipes, unix sockets and
  loopback TCP between them.
* **Network** — processes with sockets on an inner ring, their listening ports stacked above them, remote hosts on
  an outer ring, one lane per connection.
* **Memory** — a treemap of resident memory grouped by program, with system-wide totals.
* **Files** — which process has which files open, with files held by several processes highlighted.
* **Disks** — every volume and its folders as a treemap. APFS containers show their shared free space once.
* **Devices** — the IOKit hardware tree, plus network neighbours and gateways hanging off their interface.
* **LAN** — every machine on the networks this Mac is on: address, MAC, hardware vendor, the names it answers to,
  and the TCP ports it has open.
* **Trace** — type a host, an IP or a URL and watch every step between this Mac and it: the name lookup, each
  router on the way, and the conversation in ICMP, TCP, HTTP, HTTPS or DNS, decoded down to the bytes on the wire.

### What this app will not do

* **Nothing is faked.** Every number comes from the system. What cannot be measured is shown as `-`, as "not
  readable", or as the rule in force — never as a plausible zero.
* **Nothing is sent unless you ask.** No telemetry, no analytics, no update check, no crash reporting, and no
  server side. What does leave the machine, and only when you press the button for it: reverse DNS through the
  system resolver, a whois lookup, a trace, and the LAN view's sweep, name queries, port scan, SNMP read and UPnP
  query. `SECURITY.md` lists each one.
* **It does not reconfigure other machines.** The LAN view reads SNMP and UPnP; it issues no SNMP `SET`. It stores
  no credential for anything: the admin page, SSH and telnet buttons hand the session to your browser or Terminal.

### The privileged helper is optional

The app runs unprivileged by default and shows every process, all sockets and listening ports with exact byte
counts, your own processes' files and disk counters, and the full disk and device views. Installing the helper
(one administrator password prompt) adds packet capture attributed to processes, every process's open files and
counters, per-file disk I/O, process memory reading and pf firewall rules. **The helper never reads packet
contents** — it counts packets; the app itself reads bytes, only while the packet viewer is open.

### Known limits in this release

* **No MAC vendor table is bundled.** The LAN view shows the raw OUI prefix and claims no vendor. Run
  `scripts/make_oui.sh` from a source checkout to build one from the IEEE registry and rebuild the app; it is the
  only script in the project that touches the network, which is why it is not part of the build.
* **UPnP has only been tested against a router that refuses it.** The "no answer" path is verified; the path where
  a router returns its model, WAN address and port-mapping table is written but has not run against real hardware.
* **If the LAN view finds nothing, check the Local Network permission** in System Settings → Privacy & Security.
  macOS 15 and later gate outgoing local-network traffic behind it; the app declares
  `NSLocalNetworkUsageDescription` and was developed and tested on macOS 26 with the permission in force.
* **SNMP is read-only** at every version; no `SET` is ever sent. v3 supports MD5, SHA-1 and SHA-256
  authentication with AES-128 privacy; SHA-384/512 and DES are not implemented, and an agent requiring one of
  those is not answered.
* The trace speaks IPv4; an IPv6-only target is refused with a clear message rather than a silent fallback.
* Process memory reading cannot cover Apple's own binaries or hardened apps while SIP is on, and says why.
* The Disks view overstates APFS clones, and shows the volume's own "in use" figure next to the scanned total so
  the two can be compared rather than one being passed off as the other.

### Verifying the download

`SHA256SUMS` is attached. Check it against the file you downloaded, or build from source — `scripts/build.sh`
is the whole build, and there is no Xcode project to go stale.
